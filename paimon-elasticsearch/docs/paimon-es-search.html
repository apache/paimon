Query ESM1 indexes with paimon_es_search

Spark, Flink and the Java SDK share the same version-1 request, snapshot planning, field-ID binding, global reduction and result records. The Java module builds and queries Lucene archives using the published ESLib dependency.

EntryExecution
Spark paimon_es_search(catalog, request_json)Shard queries on executors; bounded global top-K and source fetch on driver.
Flink CALL catalog.sys.paimon_es_search(request_json)Shard groups on TaskManagers; bounded worker top-K followed by client merge/source fetch. Returns one JSON string per HIT/PAGE_END row.
Java EsIndexSearch.search(catalog, requestJson)Local SDK execution with the same planning, readers and bounded result.

Runtime and index prerequisites

Use JDK 11+, the matching Paimon connector and org.apache.paimon:paimon-elasticsearch with its POM runtime dependencies (published ESLib 1.0.7 and Lucene 9.12.0). The former module, artifact and profile were named paimon-eslib; Java package names and es-index remain unchanged. Keep the connector, index module and dependencies together on every worker. IK requires an additional compatible analyzer JAR.

For the module-renaming release, org.apache.paimon:paimon-eslib is published as a deprecated relocation POM pointing to paimon-elasticsearch at the same version. Maven resolves the new JAR and its dependencies when the old coordinate is used. The old -Ppaimon-eslib profile remains an alias; both profiles build the new module and the relocation POM. Source-directory selectors should use -pl paimon-elasticsearch. Scripts downloading JARs directly must use the new artifact name because the legacy coordinate publishes only a POM.

The existing Java archive format and persisted field mappings remain compatible. The module rename does not require an index rebuild.

Use an append-only data-evolution table with tracked row IDs and construction-snapshot metadata emitted by create_global_index. Spark additionally needs org.apache.paimon.spark.extensions.PaimonSparkSessionExtensions. No Elasticsearch server is required for this search entry.

CREATE DATABASE IF NOT EXISTS paimon.demo;
CREATE TABLE paimon.demo.docs (
  id INT, embedding ARRAY<FLOAT>, title STRING, tag STRING
) USING paimon TBLPROPERTIES (
  'bucket'='-1',
  'row-tracking.enabled'='true',
  'data-evolution.enabled'='true',
  'global-index.es-index.fields.embedding.dimension'='3',
  'global-index.es-index.fields.embedding.algorithm'='hnsw',
  'global-index.es-index.fields.embedding.metric'='l2',
  'global-index.es-index.fields.title.type'='fulltext',
  'global-index.es-index.fields.tag.type'='keyword'
);
INSERT INTO paimon.demo.docs VALUES
  (1, array(1.0f, 0.0f, 0.0f), 'paimon lake', 'active'),
  (2, array(0.0f, 1.0f, 0.0f), 'river meadow', 'inactive');
CALL paimon.sys.create_global_index(
  table => 'demo.docs', index_column => 'embedding,title,tag,id', index_type => 'es-index'
);

The new schema above has field IDs id=0, embedding=1, title=2, tag=3. For an existing table, read its schema IDs; do not infer them from current column positions. The index field group must match the persisted order. Query aliases bind to these stable IDs.

Text and filter-KNN examples

SELECT row_id, score, rank, source_schema_json, source_binary
FROM paimon_es_search('paimon', '{
  "version": 1, "operation": "SEARCH",
  "targets": [{
    "name": "docs", "database": "demo", "table": "docs",
    "indexes": [[1, 2, 3, 0]],
    "bindings": {"text": 2, "label": 3, "v": 1, "number": 0}
  }],
  "request": {
    "query": {"match": {"text": "paimon"}},
    "size": 10, "fetch": "SOURCE"
  }
}') WHERE record_kind = 'HIT' ORDER BY rank;

To run filter-KNN, replace the request object with:

{
  "query": {"knn": {
    "field": "v", "query_vector": [1.0, 0.0, 0.0],
    "k": 3, "num_candidates": 100,
    "filter": {"term": {"label": "active"}}
  }},
  "size": 3, "fetch": "SOURCE"
}

Put vector prefilters inside knn.filter. An outer SQL WHERE filters the returned result rows and does not change the KNN candidate set.

Supported contract

AreaBehavior
ArgumentsTwo non-null constant strings: catalog name and JSON envelope. Duplicate members, trailing JSON and unknown options are rejected before catalog IO.
TargetsOne table on main, one ordered index field group. Latest snapshot by default; explicit selector: {"kind":"snapshot","snapshot_id":"123","tag":null}.
DSLmatch_all, match_none, scalar term, terms, range, exists, match, match_phrase, bool and root-level knn with an optional filter. The persisted field mappings and analyzers determine query semantics. Java numeric terms are typed and integer fields require integral values. Temporal term, terms and range values use the stored logical type's unit: DATE is days since 1970-01-01; TIME is milliseconds since midnight; TIMESTAMP and TIMESTAMP_LTZ use Paimon's epoch-millisecond representation. Date strings and automatic unit conversion are not supported.
RankingDescending ES/Lucene score, then ascending absolute row ID for ties. Shard-local QUERY_THEN_FETCH scoring; text scores use each shard's statistics. Vector scores retain the ES/Lucene convention: larger is better.
Limitssize is positive; from + size <= 10000. KNN requires from + size <= k <= num_candidates <= 10000. At most 10,000 index shards and 100,000 data files per plan. JSON nesting is at most 32; the input is conservatively limited to 349,525 Java characters.
CompletenessEvery row range in the chosen snapshot must have one matching index generation. Unindexed appends, stale indexed columns, missing construction metadata, overlapping shards and snapshots containing deletion vectors fail explicitly. Row-level query authorization policies are rejected by the existing Paimon search guard.
Snapshot lifetimePlanning and source fetch use the same snapshot ID. This entry does not create a retention tag; callers must retain the queried snapshot and files while the query runs. Expiration or IO failures propagate as query failures.

This entry does not implement aggregation, multi-target or batch search, hybrid fusion, DFS scoring, custom sort, scan cursors, tags, source projection, global total-hit counts or rescore_vector. Only the documented bounded SEARCH contract is supported.

Result rows and source decoding

The result has 17 columns: record_kind, query_id, query_ordinal, execution_query_id, target, table_name, branch, snapshot_id, row_id, score, rank, sort_values_json, source_schema_json, source_binary, source_encoding, metadata_json, index_fields_json. Each selected hit produces HIT; a final PAGE_END record exists even for zero hits. Ranks are one-based and include the requested offset. Use ORDER BY rank when SQL result ordering matters. Sort and index-discovery columns remain null.

fetch defaults to NONE. With SOURCE, source rows are encoded with Paimon's InternalRowSerializer, include _ROW_ID, and carry the JSON row type plus the encoding label paimon-internal-row-v1. Decode with the same Paimon version. The total encoded source result is capped at 32 MiB.

RowType type = JsonSerdeUtil.fromJson(sourceSchemaJson, RowType.class);
InternalRow row = new InternalRowSerializer(type)
    .deserialize(new DataInputDeserializer(sourceBinary));

Flink and Java SDK calls

Use the same envelope shown above; target database/table identify the table within the selected catalog.

-- Flink: request_json is a constant JSON string using the same version-1 contract.
CALL paimon.sys.paimon_es_search('<request_json>');
import org.apache.paimon.globalindex.EsIndexSearch;
import org.apache.paimon.globalindex.EsSearchResult;

EsSearchResult result = EsIndexSearch.search(catalog, requestJson);
for (String record : result.jsonRecords()) {
    System.out.println(record);
}

SDK records() returns typed values in the Spark column order; jsonRecords() uses the same fields and Base64 for source_binary. Row IDs/snapshot IDs are JSON integers; clients must preserve 64-bit precision. Text scores use shard-local statistics. Java quantized KNN candidates are reranked with stored float vectors before the global merge.

Reproduce the Java tests

mvn -B -ntp -Pspark3,flink1,paimon-elasticsearch \
  -pl paimon-spark/paimon-spark-ut,paimon-flink/paimon-flink-common -am \
  -Dpaimon.es.java.tests -Dmaven.jar.forceCreation=true \
  -Dtest=EsSearch*Test,ESIndex*Test,PaimonEsSearchProcedureITCase \
  -DfailIfNoTests=false \
  -DwildcardSuites=org.apache.paimon.spark.catalyst.plans.logical.PaimonEsSearchQueryTest,org.apache.paimon.spark.query.PaimonEsSearchJavaTest \
  verify

The Java suite builds real multi-shard indexes for HNSW, INT8 HNSW and DiskBBQ, executes text, filter-KNN, pagination and source reads, and compares SDK results. Flink tests include actual TaskManager shard execution. The CI Elasticsearch/JDK 11 lane runs these tests using the published Java dependencies.
